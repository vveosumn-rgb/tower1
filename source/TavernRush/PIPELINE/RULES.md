# Правила для агентов конвейера Tavern Rush

## Окружение
- Репозиторий: `/data/work/tavernrush` (git). Перед любой сборкой: `source /data/tools/env.sh`. Там JDK 17, Android SDK 34 и Gradle 8.7.
- Машина слабая: 2 CPU и 4 ГБ RAM. Не запускайте две сборки одновременно. Если Gradle завис: `./gradlew --stop`.
- Папки `/data/tools` (инструменты) и `/data/work/pipeline` (логи, APK) не меняйте, кроме записи через `scripts/verify.sh`.
- Интернет есть, но игра полностью оффлайн. Новые runtime-зависимости не добавляйте без крайней нужды: только Kotlin, Android SDK и AndroidX, которые уже есть.

## Начало работы
1. Прочитайте `PIPELINE/VISION.md`, этот файл, `PIPELINE/BACKLOG.md`, последние 3–4 записи `PIPELINE/HANDOFF.md`, `PIPELINE/QA_CHECKLIST.md`, вывод `git log --oneline | head -40`.
2. Код изучайте точечно: `rg`, `sed -n` по диапазонам. Не выгружайте огромные файлы целиком.
3. Сначала составьте короткий план своей стадии, потом реализуйте.

## Проверка — ваши «глаза»
- `scripts/verify.sh <STAGE_ID>`, например `scripts/verify.sh R03-2`. Скрипт собирает APK, запускает unit-тесты (Robolectric с нативной графикой) и складывает PNG-скриншоты в `screenshots/`. Обзорная сетка кадров попадает в `/data/work/pipeline/logs/contact_<STAGE_ID>.png`.
- Смотрите скриншоты инструментом просмотра изображений и оценивайте картинку глазами: читаемость, красоту, баги отрисовки.
- `app/src/test/.../ScreenshotTest.kt` — сценарии скриншотов. Расширяйте его: меню, хаб, разные биомы, выбор карт, босс, экран итогов, разные разрешения. Держите его в рабочем состоянии под новый API.
- Добавляйте unit-тесты логики (урон, экономика, сохранения, античит) и бот-симуляцию забегов с метриками в `PIPELINE/METRICS.md`.
- Вся проверка должна укладываться примерно в 5 минут.

## Git
- Коммитьте часто, маленькими шагами: `git add -A && git commit -m "[R03-2] что сделано"`.
- Нельзя: `reset --hard` чужой работы, переписывать историю, force. Если работа предыдущего агента плохая, исправляйте поверх.
- К концу стадии рабочее дерево чистое, последний коммит собран, и `scripts/verify.sh` прошёл (файл `/data/work/pipeline/last_verify.txt` начинается с `OK` и содержит ваш хеш HEAD).

## Технические требования
- Kotlin, SurfaceView + Canvas, minSdk 26, портрет.
- В update/draw нет аллокаций: пулы, кэш Paint/Path/RectF/Bitmap, без лямбд и итераторов в горячем цикле.
- Цель — 60 FPS при 200+ врагах. Фиксированный шаг логики, интерполяция при необходимости.
- Арт процедурный (Canvas → кэш Bitmap при загрузке) или сгенерированный своими скриптами (Python/PIL, ImageMagick) в `tools/art/` с результатом в `res/drawable-nodpi/`. Никаких сторонних или скачанных ассетов.
- Звук процедурный (синтез в коде), без сторонних файлов.
- Тексты на русском, крупные, без обрезаний. Масштабирование UI от размера экрана, поддержка вырезов и системных отступов.
- Без рекламы, IAP, сети, аналитики и трекинга.
- Код делите на понятные модули (`core/`, `content/`, `entities/`, `systems/`, `render/`, `ui/`, `meta/`, `save/`…). Не раздувайте один файл до тысяч строк.
- Контент держите данными (таблицы и определения), чтобы следующим агентам было легко добавлять новое.

## Конец стадии (обязательно)
1. Допишите в конец `PIPELINE/HANDOFF.md` запись по шаблону из этого файла.
2. Обновите `PIPELINE/BACKLOG.md`: отметьте сделанное `[x]`, добавьте найденное с приоритетом P0/P1/P2 и тегом раунда.
3. Закоммитьте, запустите `scripts/verify.sh <STAGE_ID>`, убедитесь, что статус OK.
4. Финальное сообщение — не больше 15 строк по-русски: что сделано, ключевые цифры (сколько оружия, врагов и т. п.), статус verify, хеш коммита, главный риск или совет следующему.

### Шаблон записи HANDOFF
```
## <STAGE_ID> — <роль> — <дата>
**Сделано:** …
**Файлы:** …
**Как проверить:** …
**Известные проблемы:** …
**Совет следующему агенту:** …
```

## Принципы
- Качество важнее количества. Лучше 5 отличных механик, чем 15 сломанных. Но цели разнообразия из VISION к финалу должны быть достигнуты.
- Каждое новое решение проверяйте вопросами: делает ли это игру интереснее и радостнее? Какой инстинкт или ценность это задействует?
- Не ломайте сохранения игрока: миграции версий сейчас и в будущем.
- Работайте автономно и не задавайте вопросов. Решайте сами в духе VISION.

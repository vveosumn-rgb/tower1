# GRAPHICS_BIBLE — библия графики Tavern Rush

## Статус и назначение

Этот документ фиксирует фактический пиксельный 2.5D-конвейер R03 и правила для нового арта.
Референс — уютная таверна: тёплые огни на персонажах, холодные сине-фиолетовые тени.
Модельные значения ниже — из кода; предложения с пометкой «план» ещё не реализованы.
«AAA» здесь означает цель качества и ясную подачу, а не подтверждённый уровень релизного продукта.
Мобильный экран маленький: силуэт и опасность должны читаться до декоративной фактуры.

## Художественные опоры

| Опора | Реализованное правило |
|---|---|
| Тёплый свет | Ключ освещения сверху-слева-спереди; факелы и очаг — золотистые акценты. |
| Холодная тень | Рампа сдвигает тёмные ступени в сине-фиолетовый, а не в нейтральный серый. |
| Чёткая форма | Пиксельный контур отделяет предмет от травы; крупные детали важнее мелкого шума. |
| Материальность | Один материал получает рампу, паттерн, блеск и отдельный край. |
| Читаемость боя | Враг контрастирует с фоном; заряд, круг и кольцо показывают область удара заранее. |
| Экономия движения | Анимация меняет позу по тегам; читаемый цикл не требует плавного перерисовывания каждого пикселя. |

## Камера и проекция

Оси модели: X — продольная ось модели, Y — глубина/сторона, Z — высота.
Перед проекцией модель поворачивается по yaw; начальный yaw в ModelBuilder равен −0,42 рад.
Угол наклона камеры задан SIN = 0,5 и COS = 0,8660254, то есть 30°.
Схематическая проекция после yaw: экранный X = X′; экранный Y = Y′ × SIN + Z′ × COS.
Глубина для перекрытия использует комплементарную компоненту Y′ × COS − Z′ × SIN.
Эта формула даёт видимые верхние плоскости и бок модели без перспективного схождения.
WorldRenderer переводит единицы мира в пиксели арта через PXU = 0,5.
Иными словами, 1 пиксель модельного кадра соответствует 2 единицам мира.
Буфер мира выбирает k = ceil(ширина экрана / 380); если высота кадра ceil(высота экрана / k) получается больше 880 px, k увеличивается, пока она не уложится. Ширина кадра обычно около 360–380 px.
При экране 1080×2340 по ширине k = 3, высота 780 px укладывается в предел, поэтому внутренний кадр 360×780 px.
Кадр выводится целым масштабом без фильтрации: пиксельный край остаётся резким.

## Из объёмной модели в пиксель

| Шаг | Что делает конвейер |
|---|---|
| 1. Сборка | DSL строит тело из эллипсоидов, коробок и цилиндров, с центрами, радиусами и материалами. |
| 2. Поза | Yaw и клип анимации преобразуют детали; зеркальная сторона даёт второй ракурс персонажа. |
| 3. Подвыборка | BakeOpts.ss по умолчанию равно 2: поверхность просчитывается с подвыборкой 2×2. |
| 4. Пересечение | Лучи тестируют примитивы, выбирают видимую поверхность и записывают глубину в z-буфер. |
| 5. Свет | Нормаль поверхности освещается ключом и контровым светом; учитываются тень у земли и окклюзия. |
| 6. Материал | Освещённость выбирает ступень цветовой рампы; shine добавляет локальный блик. |
| 7. Дизеринг | Материал может использовать матрицу Bayer 4×4, чтобы переходы не стали гладкой полосой. |
| 8. Края | Перекрытие частей затемняет внутренние грани; соседние пиксели формируют внутренние линии и контур. |
| 9. Тень | Видимая геометрия проецируется на землю отдельным спрайтом; сдвиг проекции задан в ModelBaker. |
| 10. Кэш | SpriteBank сохраняет запечённые кадры и тени; тяжёлое запекание ленивое, прогрев предусмотрен. |

У конвейера есть отдельный depth/shade buffer на подвыборках и пикселях.
Контур по умолчанию опирается на PxColor.OUTLINE = #1B1224.
Внешний контур элиты золотой, контур немезиды багровый; обе вариации запекаются отдельно.
Эффекты сцены не заменяют модельную тень: world-слой добавляет собственные частицы, свет и сортировку.

## Палитра и материалы

PxColor.ramp строит пять ступеней: глубокая тень, полутень, база, свет, блик.
Для теней оттенок сдвигается к холодному; верхние ступени становятся теплее и менее насыщенными.
Значение базового цвета ограничивается сверху, чтобы оставался запас для подсветки.
Контраст рампы меняет силу hue/value/saturation сдвига без ручного рисования пяти цветов.
Материал задаётся через Mat.of(base, shine, rim, pattern, patScale, dither, outline, contrast).
Самосветящиеся глаза, огонь и самоцветы задаются через Mat.glow(base, outline).
У Mat.glow световая рампа плоская и не зависит от обычного освещения.
По умолчанию край материала смешивает самую тёмную ступень с общим тёмным контуром.
Паттерн используйте только для крупной материальной подсказки; микродетали на телефоне сливаются.

| Паттерн | Допустимое назначение |
|---|---|
| NONE | Кожа, большие формы и однотонные участки. |
| STRIPES | Ткань, ремни, маркировка. |
| CHECK | Крупная клетка и сетка. |
| NOISE | Камень или сдержанная неоднородность поверхности. |
| DOTS | Пятна, чешуя и точечный декор. |
| PLANKS | Дерево, доски и мебель. |

## Модели, анимация и сцена

ModelBuilder предоставляет ell, box, cyl, симметричную пару pair и регистрацию клипа.
Tag описывает движущиеся части: ноги, руки, голова, тело, хвост, крылья, оружие, плащ и челюсть.
Anims задаёт ходьбу, покой, четвероногий шаг, прыжок, взмах крыльев, парение и удар.
Типовые walk/quad/hop/flap/hover используют 6 кадров, idle — 4; модели могут переопределить число.
Удары slam/rear для боссов используют по 6 поз; SpriteBank хранит левое и правое направление.
Поворотные снаряды могут запекаться в 16 направлениях; это не значит, что у каждого оружия 16 циклов.
Частота смены кадров ходьбы задаётся по EnemyLook в WorldRenderer: таблица содержит значения от 5 до 14 кадров/с.
Сортировка врагов, героя, реквизита и орбитального оружия выполняется подсчётом по глубинным bucket-ключам.
PixelAssets создаёт бесшовную траву, декор, облачные тени и свечения; PixelFont выводит числа.
GroundLayer накладывает траву и облака; WorldRenderer сейчас подключает только палитру Biomes.MEADOW.
Частицы имеют высоту Z и скорость по Z; доступны пыль, искры, дым, звёзды, угли, обломки, блёстки, монеты, листья и mote.
MainActivity запускает SpriteBank.warmUpAsync; фоновый прогрев включает клипы, элитные и именные варианты обычных врагов.

## R02 → R03: проверяемые изменения

Сравнение R02 взято из приложенного архива исходников, а не из оценки по скриншотам.
Число «моделей» ниже различает художественные семейства и фабрики ModelBuilder.
Не следует обещать удвоение качества по одной только арифметике количества ассетов.

| Показатель | R02: исходный векторный Canvas-арт | R03: пиксельная 2.5D |
|---|---|---|
| Персонажи | 4 стиля героя и 5 видов врага; формы рисуются Canvas-путями и кэшируются в Bitmap. | 4 героя, 12 маршрутов EnemyLook (один — масштабированный слизень), 3 босса. |
| Кадры | Враг: 2 кадра; герой: 3; обе серии зеркалятся по горизонтали. | Типовой цикл: walk 6, idle 4; boss slam/rear 6; обычно два направления. |
| Поворот | Зеркало влево/вправо; без общей сетки направлений для всего арта. | Снаряды с bakeHeadings запекаются в 16 направлений; персонажи — зеркальная пара. |
| Освещение | Цветная заливка, контур, заранее нарисованные тень, aura и radial glow. | Лучевая поверхность, z-буфер, нормали, рампы, окклюзия, контровой свет и эмиссия. |
| Тени | Кэшированный спрайт тени/пятно. | Проекционная тень от модельной геометрии плюс игровые тени сущностей. |
| Эффекты | Canvas-партиклы, кольца, лучи и screen shake; не считать их отсутствующими в R02. | Высотные частицы, свет, ring, hit-stop, bloom, aberration, grading и flash. |
| Формы | 9 семейств персонажей: 4 героя + 5 обычных врагов. | 19 маршрутов персонажей: 4 героя + 12 EnemyLook + 3 босса. |
| Фабрики модели | Специализированного DSL объёмных моделей нет. | 40 фабрик моделей: 4 Hero + 11 Enemy + 3 Boss + 22 Prop. Slimelet — вариант фабрики slime. |

## Как добавить модель

1. Выбрать геометрию из ell/box/cyl; модель должна читаться в силуэте без свечения.
2. Добавить фабрику в нужный файл: HeroModels.kt, EnemyModels.kt, BossModels.kt или PropModels.kt.
3. Назначить базовые Mat.of материалы; Mat.glow оставить для реально светящихся частей.
4. Проставить Tag движущимся деталям и прикрепить подходящий Anims-клип.
5. Зарегистрировать геройский индекс или EnemyLook в ModelLibrary.kt; новый look должен быть обработан exhaustively.
6. Убедиться, что SpriteBank.kt печёт walk/idle/attack по нужным клипам; пропы и снаряды регистрируются там же.
7. Для вращаемого снаряда использовать bakeHeadings; для поворота шагов проверить частоту WALK_FPS в WorldRenderer.kt.
8. Сохранить форму при зеркалировании и проверить footDrop, хитбокс, тень и направление движения.

## Чек-лист арта и долг

| Проверка | Критерий |
|---|---|
| Силуэт | Узнаётся на маленьком кадре и не совпадает с ближайшим врагом. |
| Контраст | Тёмный контур и светлая/тёмная крупная масса отделены от травы. |
| Материал | Рампа читается; паттерн не шумит и не имитирует лишний контур. |
| Анимация | Цикл не мерцает, ноги не отрываются от тени, атака предвосхищает попадание. |
| Удар | Телеграф заметен до урона и отличается цветом/формой от декора. |
| Производительность | Кадры кэшируются; не запускать запекание при каждом draw. |
| Мобильный масштаб | Проверить базовый экран, минимальную ширину и планшет; не полагаться на цвет один. |

| Долг | Статус |
|---|---|
| Разные игровые биомы | План: R04; код сейчас использует одну MEADOW-палитру. |
| Пиксельный фон меню | План: меню рисует отдельный Canvas-backdrop, не этот pixel-model конвейер. |
| Эволюционные формы оружия | План: есть названия/значки эволюции, нет отдельных эволюционных 3D-моделей. |
| Модели сверх текущего состава | План: цели VISION — больше врагов и боссов; не считать цель закрытой. |
| Проверка на устройствах | Не подтверждена этим документом; нужны свежие скриншоты и измерения. |
